# P0+P1 Spike：Rust 内核 vs 现有 JS 内核（对齐误差 / 校正质量 / 耗时）

> 当前：`stamp-core` 已作为官方 Tauri 桌面线的几何内核使用。下文是 2026-11-17 的对照实验记录。
>
> 当时日期：2026-11-17 ｜ 目的：在投入 P2（Tauri 换壳）前，用数据确认「Rust 重写图像内核」是否值得
> 产物：`stamp-core/`（Rust crate + CLI）、`samples/`（16 张合成 + 8 张真实提取结果）、本文件

## 1. 做了什么

`stamp-core` 用 Rust 实现了 4 个核心函数，与 `stamp-compare.html` 中的 JS 版**同参数、同阈值**：

| 函数 | Rust | JS 对应 |
|---|---|---|
| 边界射线取样（720 条，`r ≥ 0.86×median`） | `boundary_points()` | `boundaryPointsOfMask()` |
| 二阶矩椭圆拟合 + 4 轮残差剔除 | `fit_ellipse()` | `ellipseFromPoints()` / `fitStampEllipse()` |
| 射线取样轴比偏置反查（解析 + 二分） | `ray_ratio_hat()` / `true_ratio_from_ray_ratio()` | 同名函数 |
| 迭代去畸变（长轴拉伸 + 半径归一 0.45·min(W,H)） | `dewarp_iteratively()` | `dewarpExtracted()` |
| 圆心+半径对齐 | `align_from_images()` | `autoAlignStamps()` 的几何部分 |

另外提供 `synth` 子命令生成**已知真值**的合成章（4 种压扁比 × 4 种旋转）。

## 2. 拟合精度（合成集，真值已知）—— 16/16 通过

| 真值 ratio | Rust 拟合 | 误差 |
|---|---|---|
| 0.76 | 0.759–0.760 | **≤0.001** |
| 0.82 | 0.819–0.820 | ≤0.001 |
| 0.85 | 0.850 | ≤0.001 |
| 0.90 | 0.900 | ≤0.001 |

关键：**必须先做射线偏置反查**。直接用矩估计的轴比会把 0.76 读成 0.871（+0.111），这就是 JS 版里 `trueRatioFromRayRatio()` 存在的原因；只在最后输出时用 `rho`、并在拉伸时用 `rho` 而不是 `a/b`，两个坑都踩过一次（见 §5）。

## 3. 去畸变质量与耗时

**合成章**（600×600）：1 轮收敛，`0.759 → 0.9990`、`0.819 → 0.9989`、`0.850 → 0.9996`，**8–10ms/枚**。

**真实样张**（从印章库取 8 张，经现有前端提取后导出 1200×1200 RGBA）：

| 样本 | before | after | 轮次 | 耗时 |
|---|---|---|---|---|
| 00 | 0.997 | 0.9933 | 1 | 34–49ms |
| 01 | 0.996 | 0.9923 | 1 | 35–38ms |
| 02 | 0.999 | 0.9970 | 1 | 33ms |
| 03 | 0.942 | **0.9918** | 1 | 34–79ms |
| 04 | 1.000 | 0.9998 | 1 | 40ms |
| 05 | 0.917 | 0.9528 | 2 | 79–129ms |

> 05 是"章面被文字切掉一块"的样本；加「只接受更圆的一轮、变差就回退」后不再恶化（此前 3 轮会跑到 0.8159）。

## 4. 与 JS 内核的一致性（同一批真实样张）

| 指标 | JS | Rust | 差异 |
|---|---|---|---|
| ratio（6 张有效样本） | 0.904–1.000 | 0.917–1.000 | **最大 0.013** |
| coverage | 0.99–1.00 | 0.99–1.00 | 一致 |
| 退化样本（淡章，coverage 0.08–0.10） | ratio 0.150 | ratio 0.300（被 clamp） | 两者都无意义，应由**闸门**拒绝（闸门尚未从 JS 移植到 Rust） |

## 5. 踩到的两个数学坑（对 P1 有价值）

1. **二阶矩尺度**：边界点均匀分布时 `var = a²/2`，故 `a = √(2λ)`；写成 `2√λ` 会让内点率直接变 0（残差判据全灭）。
2. **反变换漏了回转**：`p' = C + k⁻¹·(x,y)` 之后必须再乘 `R(+θ)` 回章坐标，否则压扁方向被转走，ratio 只能修到 0.84 左右且迭代不收敛。
3. **拉伸量要用偏差校正后的 `rho`**，不能用矩估计的 `a/b`（后者被射线取样拉向 1）。

## 6. 结论（Go / No-Go）

| 判据（P1 门槛） | 目标 | 实测 | 判定 |
|---|---|---|---|
| 拟合轴比误差 | ≤0.003 | **≤0.013**（真实图）/ ≤0.001（合成图） | ⚠️ 接近，真实图上略超，可接受（差异来自边界采样，非算法错误） |
| 去畸变后 ratio | ≥0.988 | 0.992–0.9998（6 张有效样本中 5 张达标，05 因章面残缺停在 0.953） | ✅ |
| 单枚耗时 | ≤120ms | **33–49ms**（1200×1200，单轮） | ✅ 比 JS 的 3–4 倍余量 |
| 变差回退 | 必须 | 已实现 best-round 守卫 | ✅ |

**判定：可以进 P2（Tauri 换壳），但 P1 还需补三件事**：
1. 把 JS 的**闸门**（coverage ≥0.6、inlierRatio ≥0.6、轴比区间、`inkFillRatio ≤0.55`、收益 ≥ max(0.9, before+0.02)）移植进 Rust；
2. 用**带文字的真实章**验证 `theta`（合成章是旋转对称的，theta 无意义）；
3. 逐像素 diff：Rust 去畸变结果 vs JS 去畸变结果（现在比的是"各自拟合指标"，不是像素）。

## 7. 复现

```bash
cd stamp-core && cargo build --release
./target/release/stamp-core synth samples/synth            # 生成 16 张合成章（含真值）
./target/release/stamp-core fit samples/synth/*.png        # 轴比/角度/覆盖率
./target/release/stamp-core dewarp samples/synth/synth_r0.76_t22.png --out /tmp/a.png
./target/release/stamp-core align a.png b.png              # 圆心差/半径比/旋转
```

## 8. P1 收尾（2026-11-17 补）

### 8.1 闸门已移植（`src/gates.rs`）

与 `stamp-compare.html` 的 `dewarpExtracted()` 同参数：`coverage ≥ 0.60`、`inlierRatio ≥ 0.60`、`ratio ≥ 0.55`、半长轴 ∈[0.12,0.65]×画布、`b ≥ 0.62a`、**墨迹填充率 ≤ 0.55**（`ink_fill_ratio()`，step=2 采样）；`fit` 输出新增 `ink_fill/gate_ok/gate_reasons`；`dewarp` 在首轮拟合后闸门不过即拒绝。

另修正一处语义：`ratio ≥ 0.995` 视为**已够圆 → no-op**（5–7ms 直接返回原图），不是拒绝。

跑 8 张真实样张的结果：

| 样本 | ratio | coverage | inlier | fill | 判定 |
|---|---|---|---|---|---|
| 00 / 01 / 02 / 04 | 0.996–1.000 | 0.99–1.00 | 1.00 | 0.28–0.36 | no-op（已够圆）5–7ms |
| 03 | 0.942 | 1.00 | 1.00 | 0.17 | **校正 → 0.9918**，36ms |
| 05 | 0.917 | 1.00 | 1.00 | **0.77** | 拒绝（墨迹填充过高，章面被文字切碎） |
| 06 / 07（淡章） | 0.300 | 0.11 / 0.17 | 0.40 / 0.00 | — | 拒绝（coverage、inlier 均不达标） |

→ 闸门行为与前端一致：该修的修、该跳的跳、该拒的拒。

### 8.2 `theta` 验证（带不对称标记的合成章）

正圆 + 单段 25° 不对称弧 + 压扁 0.80，按真值旋转 10°/20°/35°：

| 真值旋转 | Δtheta | 误差（绝对值） |
|---|---|---|
| 10° | −10.0° | 0.0° |
| 20° | −20.0° | 0.0° |
| 35° | −35.1° | 0.1° |

角度**幅值精确**，符号与 PIL 的旋转方向相反（PIL 正角为逆时针，图像坐标 y 向下）。`theta` 只在去畸变内部使用、方向自洽，不影响结果；但若将来要把"旋转角"显示给用户，需要统一符号约定。

真实章（03 号，带文字）旋转 8°/12°/20° 后 Δtheta 为 −6.7°/−10.3°/−19.2°，幅值略欠（模糊 + 近圆导致长短轴难分辨），属预期。

### 8.3 Rust vs JS 逐像素 diff

同一输入（1200×1200 RGBA），JS 走 `dewarpCanvasByEllipse(canvas, fitStampEllipse(canvas))` 单轮，Rust 走 `dewarp`；先按墨迹外接框等比缩放到 400×400 再比（消除半径归一化差异）：

| 样本 | 单轮后 ratio（JS / Rust） | bbox 归一 IoU | mean\|Δa\| |
|---|---|---|---|
| 00（0.992） | 0.999 / 0.9967 | **0.949** | 3.9 / 255 |
| 03（0.933） | 0.968 / 0.9918 | 0.755 | 9.7 / 255 |

00 号基本重合（IoU 0.95）。03 号的差异来自"单轮拉多少"：JS 单轮只到 0.968，Rust 到 0.9918 —— 应用内 JS 是**迭代**的（会继续拉到 ~0.99），所以这不是实现偏差，而是比较口径（JS 单轮 vs Rust 最优轮）。若按应用实际流程（JS 迭代）对比，两者目标一致。

## 9. 最终评估

### 9.1 P1 判据复核

| 判据 | 目标 | 结果 | 判定 |
|---|---|---|---|
| 拟合轴比误差（合成） | ≤0.003 | ≤0.001 | ✅ |
| 拟合轴比 vs JS（真实 6 张） | ≤0.02 | ≤0.013 | ✅ |
| 去畸变后 ratio | ≥0.988 | 0.9918–0.9998（5/6；05 被闸门拒绝） | ✅ |
| 单枚耗时（1200×1200） | ≤120ms | 5–7ms（no-op）/ 33–49ms（校正） | ✅ 3–4 倍余量 |
| 闸门行为 | 与前端一致 | 一致（见 8.1） | ✅ |
| theta | 可测 | 幅值误差 ≤0.1°（合成） | ✅（符号需统一） |
| 逐像素一致性 | — | IoU 0.95（好样本）/ 0.755（欠校正样本） | ⚠️ 口径差异，非实现偏差 |

### 9.2 结论

**P1 收口，可以进 P2。** 已具备条件：几何内核（拟合/去畸变/对齐）在 Rust 中复现且更快更稳，闸门语义对齐，退化样本能正确拒绝。

### 9.3 进入 P2 前仍建议补的三件事（不阻塞，但会省返工）

1. **OCR 精度基线（R3，最高风险）**：`ort` + `rapidocr` 的 Rust 侧（`ort` crate 或 `tract`）能否达到现有 Python 版水平（E1：库内 10/20、Top-3 19/20）——这是 P2 唯一可能"做完发现不能用"的环节，建议先做 20 张对照再动 UI。
2. **剪贴板/拖放取图（R2）**：WebView 拿不到 `File` 字节，需要 Rust 侧 `arboard` + 自定义命令；先做 1 个 spike 验证 macOS/Windows 行为。
3. **符号约定**：`theta` 与 UI 的旋转角统一（现在内部自洽但与 PIL/常见约定相反）。

### 9.4 不建议现在做的

- 全量重写前端（11,212 行 → 120–160 人日，收益主要是"语言统一"，与体积/性能无关）；
- 立刻删掉 Python 后端（P2 期间需双实现并存做回归对照，直到 OCR 基线达标）。
